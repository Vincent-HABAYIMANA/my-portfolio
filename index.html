Section 01

What is Deployment?
And How is it Different from Hosting?

When you build a website or web app on your computer, only you can see it. Nobody else in the world can visit it. To share it with others, you need two things: deployment and hosting. Many beginners confuse these two — let's clear that up!

🏠 Real-life analogy Think of your project like a restaurant. You cook the food at home (building the project). Hosting is like renting a physical building where your restaurant will live. Deployment is the act of moving everything — tables, chairs, menus, and food — into that building and opening the doors to customers.

🔵 What is Hosting?

Hosting is simply a place on the internet where your website files are stored. Think of it as renting a room on a big server computer somewhere in the world. That computer is always on, 24 hours a day, 7 days a week. So whenever someone types your website address, their browser goes to that computer and gets your files.

Examples of hosting providers: Vercel, Netlify, GitHub Pages, Render.

🔴 What is Deployment?

Deployment is the process of uploading your code from your computer to a hosting server. When you deploy, your project goes from "sitting on your laptop" to "running live on the internet."

ConceptSimple meaningReal-life example
Hosting The place where your website lives online Renting an apartment
Deployment The action of putting your website there Moving your furniture into the apartment
Build Preparing your code to run on a server Packing your boxes before moving
Live site Your website that everyone can visit The apartment after you moved in
With Vercel, hosting and deployment happen together — you just push your code, and Vercel handles everything else automatically!

Why Do We Need Deployment?

You need deployment when you want to:

  • Share your project with friends, teachers, or clients
  • Put your project in your portfolio / CV
  • Let users around the world access your web app
  • Test how your project works on a real server
Section 02

How to Prepare a Project for Deployment

Before you deploy, you need to make sure your project is clean and ready. Think of it like cleaning your house before guests arrive. Here's what that means:

1

Make sure it runs correctly on your computer

Open your project in the browser locally. If there are errors in the console (press F12 to see), fix them first. A broken project locally = a broken project online.

2

Put your project in a GitHub repository

Vercel connects directly to GitHub. If you don't have a GitHub account yet, create one at github.com. Then upload your project there. GitHub is like Google Drive but specifically for code.

3

Check your file structure

Make sure you have an entry point file. For HTML projects: index.html. For React: package.json with a start script. Vercel needs to know where your project begins.

4

Remove sensitive information

Never put passwords, API keys, or database credentials directly in your code. Use environment variables instead (explained in Section 6). Adding a .gitignore file helps prevent accidental uploads.

5

Test on a different browser

Open your project in Chrome AND Firefox. Sometimes things look different across browsers. Fix any differences before deploying.

The Basic File Structure Vercel Expects

For a simple HTML website, your folder should look like this:

my-project/
├── index.html        ← main page (REQUIRED)
├── style.css         ← your styles
├── script.js         ← your JavaScript
└── images/           ← your images folder
    └── logo.pngFOLDER STRUCTURE

For a React project (created with Vite or Create React App):

my-react-app/
├── package.json       ← project info & scripts (REQUIRED)
├── src/
│   ├── main.jsx       ← entry point
│   └── App.jsx
├── public/
│   └── index.html
└── .gitignore         ← files to ignoreREACT STRUCTURE
Never delete package.json from a React project. Vercel reads it to understand how to build your project. Without it, deployment will fail.

Creating a .gitignore File (Important!)

A .gitignore file tells Git (and therefore GitHub) which files NOT to upload. For a React/Node project, create a file named .gitignore in your root folder with this content:

node_modules/
.env
.DS_Store
dist/
build/.gitignore
The node_modules folder can have thousands of files. You never need to upload it — Vercel will download them automatically.

Section 04

Types of Projects Supported by Vercel

Vercel is very powerful — it supports many types of web projects. As a beginner, you'll mostly use the first two. But it's good to know what else exists!

✅ Vercel Supports These Project Types:

📄 Plain HTML / CSS / JS websites
⚛️ React (Create React App)
⚡ React + Vite
🔷 Next.js (React framework)
🟢 Vue.js
🔥 Svelte / SvelteKit
🅰️ Angular
⚙️ Node.js APIs (serverless)
🐍 Python (Flask, FastAPI)
💎 Ruby
🐘 PHP
As a Year 3 student, focus on deploying HTML/CSS/JS and React (Vite) projects first. These are the most common and easiest to deploy.

What Vercel Does NOT Support Directly

Vercel is built for frontend and serverless projects. It does NOT work well for:

Not SupportedWhyAlternative
Full Django / Spring Boot servers These need a persistent server running all the time Use Render.com or Railway
Traditional MySQL databases Vercel doesn't host databases Use PlanetScale, Supabase, or MongoDB Atlas
Desktop apps (Java Swing, etc.) Vercel is web-only GitHub Releases for downloads
🍽️ Analogy Vercel is like a food truck — fast, efficient, and perfect for serving web pages quickly. But if you need a full kitchen with refrigerators and storage (databases, persistent servers), you need a full restaurant (different service).
Section 05

Step-by-Step Deployment Guide

From Zero to Live Site — follow each step carefully. We'll deploy a project using GitHub + Vercel.

🔧 Before You Start — What You Need

  • ✅ A GitHub account (github.com)
  • ✅ A Vercel account (vercel.com) — you can sign up with GitHub
  • ✅ Git installed on your computer (git-scm.com)
  • ✅ A project folder on your computer

📦 Phase 1 — Put Your Project on GitHub

1

Create a new repository on GitHub

Go to github.com → Click the green "New" button → Give your repo a name (e.g., my-portfolio) → Keep it Public → Click "Create repository".

2

Open your terminal and go to your project folder

Open your terminal (or VS Code terminal). Navigate to your project:

# Example: if your project is on the Desktop
cd Desktop/my-portfolio

# Check you're in the right place (you should see your files)
lsTERMINAL
3

Initialize Git and connect to GitHub

Run these commands one by one (replace the URL with YOUR repository URL from GitHub):

git init                          # Start tracking this folder with Git
git add .                         # Stage ALL your files
git commit -m "First commit"      # Save a snapshot of your files

# Connect to your GitHub repository (get this URL from GitHub)
git remote add origin https://github.com/YOUR-USERNAME/my-portfolio.git

git branch -M main                # Rename branch to "main"
git push -u origin main           # Upload to GitHub!TERMINAL — Git Commands
After running these commands, refresh your GitHub repository page. You should see your files there!

🚀 Phase 2 — Deploy on Vercel

4

Sign in to Vercel

Go to vercel.com → Click "Sign Up" → Choose "Continue with GitHub". This links your GitHub account to Vercel automatically.

5

Create a new project

On the Vercel dashboard → Click the "Add New…" button → Select "Project".

6

Import your GitHub repository

Vercel will show a list of your GitHub repositories. Find my-portfolio and click the "Import" button next to it.

7

Configure the project (usually nothing to change!)

Vercel is smart. It will automatically detect if you have a React, Vite, or HTML project and set the right build settings. For plain HTML projects, no changes are needed. Click "Deploy"!

8

Wait for deployment (30–60 seconds)

You'll see a progress screen with logs. Vercel installs dependencies, builds the project, and publishes it. When you see the confetti/success screen — YOU'RE LIVE! 🎉

9

Copy your live URL!

Vercel gives you a URL like my-portfolio.vercel.app. Share it with anyone! Open it on your phone, send it to your lecturer, add it to your CV.

🔄 How to Update Your Live Site

One of the BEST things about Vercel is automatic redeployment. Every time you push code to GitHub, Vercel automatically updates your live site. You never need to manually deploy again!

# Make changes to your files, then:
git add .
git commit -m "Updated my homepage"
git push                          # Vercel sees this and auto-redeploys!TERMINAL — Update Workflow
🔁 Analogy It's like having an assistant who watches your desk (GitHub). Every time you update a document (push code), they immediately update the notice board on the wall (your live site) automatically — you don't have to do anything extra.
Section 06

Understanding the Vercel Dashboard

After you deploy, you'll spend time on the Vercel dashboard. Let's walk through what everything means so you're not confused.

🏠 Overview (Home)

Shows all your deployed projects. Each project has a preview image, the live URL, and the last time it was updated.

🚀 Deployments Tab

Every time you push to GitHub, a new deployment is listed here. You can see if it succeeded (✅) or failed (❌), and view the build logs.

📊 Analytics Tab

Shows how many people visited your site, which pages they went to, and where they came from. (Basic analytics on the free plan.)

⚙️ Settings Tab

Where you configure your project: change the name, set environment variables, manage domains, and control build settings.

🌐 Domains Section

By default you get a yourproject.vercel.app URL. Here you can connect a custom domain like yourname.com if you own one.

📋 Build Logs

When a deployment fails, click "View Deployment" → "Build Logs". This shows the exact error so you can fix it. Always read the last few lines — that's where the error usually is.

🔐 Environment Variables — Keeping Secrets Safe

Sometimes your project needs a secret key (like an API key for weather or maps). You should never put this directly in your code. Instead, use environment variables.

Think of an environment variable like a secret note that Vercel reads but nobody else can see in your code.

# ❌ WRONG — Don't do this in your code!
const apiKey = "abc123secretkey456";

# ✅ CORRECT — Use an environment variable
const apiKey = process.env.MY_API_KEY;JavaScript

To add an environment variable on Vercel:

→

Go to your project → Settings → Environment Variables

Type the Name (e.g., MY_API_KEY) and the Value (e.g., abc123secret). Choose which environments it applies to (Production, Preview, Development). Click Save. Then redeploy.

Section 07

Practical Exercise

It's time to deploy your own project! Follow these tasks step by step. By the end, you will have a real, live website with a public URL.

🎯 Exercise Goal

Deploy Your First Live Website

By completing this exercise, you will have a project deployed on Vercel with a public .vercel.app URL that anyone in the world can visit.

📋 Task 1 — Create the Project (30 minutes)

Create a simple HTML portfolio page. Use the template from Section 3 OR build your own with these requirements:

  • Has an index.html file as the main page
  • Shows your name and a short description of yourself
  • Lists at least 2 projects you've worked on (even if small)
  • Has some CSS styling (colors, fonts, spacing)
  • Has at least one link (GitHub, email, or project link)
  • Opens without errors in your browser

📋 Task 2 — Push to GitHub (20 minutes)

Follow the Git commands from Section 5. When done, verify these things:

  • Created a GitHub account if you didn't have one
  • Created a new public repository called my-portfolio
  • Ran git init, git add ., git commit
  • Ran git push successfully
  • Can see your files on GitHub in the browser

📋 Task 3 — Deploy on Vercel (10 minutes)

  • Created a Vercel account using GitHub login
  • Imported the my-portfolio repository
  • Clicked Deploy and waited for it to finish
  • Got a successful "Congratulations" screen
  • Opened the live .vercel.app URL
  • Verified the website looks correct in the browser

📋 Task 4 — Make an Update (10 minutes)

This tests the automatic redeployment feature:

  • Changed something in your index.html (e.g., changed a color or added text)
  • Ran git add . && git commit -m "Updated site" && git push
  • Watched the Vercel dashboard show a new deployment
  • Refreshed your live URL and saw the change applied

🏆 Submission

Share Your Live URL

When you finish, share your yourname.vercel.app URL with your lecturer or classmates. Add it to your GitHub profile and your CV!


Bonus: Try deploying a React project using Vite (npm create vite@latest) and repeating the same process. The steps are exactly the same — Vercel detects React automatically!

🐛 Common Problems and Fixes

ProblemWhat's WrongSolution
Page shows "404 Not Found" Your main file is not named index.html Rename your main file to index.html
Build failed — "module not found" You forgot to push package.json Run git add . && git push again
Images not loading Image file paths are wrong (case-sensitive on servers) Make sure paths match exactly: images/Photo.png ≠ images/photo.png
CSS not applying CSS file path wrong in <link> tag Check: <link rel="stylesheet" href="style.css"> matches your file name
Deployment stuck "building" Rarely: Vercel issue Wait 5 min. If still stuck, go to deployments → cancel → redeploy
